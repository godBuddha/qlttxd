=== NHIEM VU 1 — HC-01 (P0, Risk 9/10): TTL drift giua JWT va refresh_tokens row ===

Van de: routes/auth.js co 3 cho INSERT INTO refresh_tokens voi SQL hardcode "now() + interval '7 days'" (dong ~175, ~260, ~354), trong khi JWT refresh token duoc ky voi expiresIn = cfg.getSync('auth','jwt_refresh_ttl','7d'). Khi admin doi jwt_refresh_ttl qua Settings, JWT va expires_at trong DB LECH NHAU → refresh token bi tu choi som/muon bat thuong, hoac ton tai qua han chinh sach.

CACH FIX:
1. Tao helper parse TTL string → so ngay, dat o dung cho (vd utils/helpers.js hoac tao utils/ttl.js):
   - Input: chuoi nhu '7d', '12h', '30m', '45s' (dung dinh dang ma jsonwebtoken chap nhan)
   - Output: so GIAY (integer)
   - Xu ly: regex /^([0-9]+)([smhd])$/ ; s=1, m=60, h=3600, d=86400. Khong khop → throw Error ro rang.
   - Viet unit test cho helper (hop le, bien gioi, sai format).

2. Thay 3 cau SQL INSERT:
   TRUOC: INSERT INTO refresh_tokens (user_id, jti, expires_at) VALUES ($1, $2, now() + interval '7 days')
   SAU:  INSERT INTO refresh_tokens (user_id, jti, expires_at) VALUES ($1, $2, now() + make_interval(secs => $3))
   - Truyen tham so thu 3 = so giay tu helper, doc tu cfg.getSync('auth','jwt_refresh_ttl','7d') (trong authRoutes da co cfg — kiem tra lai scope bien; neu chua co thi them).
   - KHONG dung string interpolation cho gia tri so — bat buoc parameterized $3.

3. Test hồi quy (them vao test co lien quan hoac test moi):
   - Login → query refresh_tokens.expires_at → so sanh khoang cach with now() ≈ TTL seconds (cho phep lech ±5s do mat tg request).
   - Case TTL mac dinh '7d'.
   - Neu co the mock config TTL khac (vd '1h') thi verify tiep; khong thi ghi nho trong report.
